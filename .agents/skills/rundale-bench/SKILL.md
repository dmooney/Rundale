# rundale-bench

Unified model-quality eval. Candidate replies are generated by the Python
orchestrator; **judging is done by Claude Sonnet 4.6 subagents launched from
this session**. The orchestrator and the subagents communicate through an
on-disk queue, so a run can be aborted and resumed at any point.

## The loop

```
1. python rundale-bench/rundale_bench.py run …      # generate samples → .bench-queue/pending/
2. /rundale-bench drain-queue                        # YOU dispatch judge subagents → .bench-queue/done/
3. python rundale-bench/rundale_bench.py ingest --finalize   # validate + cache + aggregate
```

(Phase 1 wires the **dialogue** slice. The legacy single-target run uses
`--judge sonnet`; the tier funnel arrives in Phase 2.)

### Step 1 — generate samples

Run the orchestrator for one or more candidates with the Sonnet judge selected:

```sh
python rundale-bench/rundale_bench.py --target '<model>@<base_url>[#env:VAR]' \
    --slice dialogue --judge sonnet --tier screen \
    --model-id <catalog-id> --provider-id <provider>
```

This writes one bundle per candidate to `rundale-bench/.bench-queue/pending/`
and a run JSON under `rundale-bench/artifacts/`. It makes **zero** judge calls.
Already-judged (prompt, response) pairs are served from the committed cache and
are not re-queued.

### Step 2 — drain-queue (this is your job)

For every bundle in `rundale-bench/.bench-queue/pending/` that has no matching
file in `done/`:

1. Read the bundle JSON.
2. Dispatch an `Agent` subagent (batch up to **8 in parallel** per message to
   stay within rate limits) running the `/rundale-bench-judge` skill, passing
   the bundle file path. The subagent uses the system prompt named in the
   bundle's `system_prompt_file` (`judge_sonnet_v1.system.md`) and returns a
   single JSON object — nothing else.
3. Write the subagent's JSON reply verbatim to
   `rundale-bench/.bench-queue/done/<bundle_id>.json` (same stem as the
   pending file).

**Resume semantics:** a bundle is "done" iff `done/<stem>.json` exists. Re-running
drain-queue only dispatches bundles still missing a `done/` file, so an
interrupted run is safe to restart. Never edit a `pending/` bundle by hand.

### Step 3 — ingest

```sh
python rundale-bench/rundale_bench.py ingest --finalize
```

Validates each `done/` result against its bundle (rubric_sha256 must match;
axes must be ints 1-5; every prompt must be scored), writes content-addressed
judgments to `docs/proofs/rundale-bench/judgments/<cache_key>.json`, and folds
the scores back into the run JSON aggregate. `--finalize` errors if any
pending bundle is still unjudged. Malformed or dropped items are reported as
judge failures and excluded from the aggregate (re-dispatch to retry).

## Inspect

```sh
python rundale-bench/rundale_bench.py catalog --show          # models + resolved providers
python rundale-bench/rundale_bench.py judge --verify sonnet   # rubric_sha256 integrity
```
