# LEARNINGS — gotchas for future maintainers

Brief notes worth a future agent's time. Append new entries at the
bottom; don't lengthen items past 2-3 lines.

## Engine + runtime

- **`parish-cli` package is now named `parish-repl`** (binary `parish-repl`). Use `cargo run -p parish-repl`. The lib inside keeps the name `parish` so internal `use parish::` paths still work.
- **New `parish-client` crate builds the `parish` binary** — thin HTTP client calling `POST /api/command` on a running server. Use `cargo run -p parish-client` or `just run-client`.
- **`--script` runs `run_script_mode` → `GameTestHarness`**, NOT `run_headless`. Different code path. Wire features in both.
- **`apply_movement` (in `parish-core/src/game_session.rs`) is the lowest-shared movement seam.** Tauri/server reach it via `game_loop::movement::handle_movement`; the script harness calls `apply_movement` directly. Publish movement-related events there for parity.
- **The world-advance pump is `parish_core::game_loop::advance_world` (#1159) — the ONE place weather/schedules/tiers/banshee/gossip/tier-4 are ticked.** Each runtime selects atoms via `AdvanceOptions` (server: `GossipMode::Budgeted` + `run_tier4:false`; Tauri: `All`+tier4; headless: `Single` weather + tier4, no gossip; harness per-turn: everything off but banshee; `advance_time`: `Backfill` weather + `All` gossip + tier4). RNG order is always weather→gossip→tier-4 so seeded harness runs stay byte-stable. Don't re-inline any of these atoms into an entry-point loop — the `entry_point_crates_do_not_reimplement_shared_commands` fitness test (allowlist now empty) will reject a `Command::Wait/Tick =>` arm, and `advance_world` is where new pump atoms belong.
- **`snapshot.restore` wipes `tier_assignments`** — fixed by calling `npc_manager.seed_tier_state(world)` at the end of `restore`. The seed function is in `parish-npc/src/tier_assign.rs` and shares its BFS distance compute with `assign_tiers` but publishes no events. Tier is derivable from `(player_location, npc.location, npc.state)` so the snapshot file itself doesn't need to carry it.
- **`GameTestHarness::new()` runs in hundreds of tests.** Never default a side-effecting writer (filesystem, network) on in `new()` — `new_with_<feature>()` opt-in or env-var gate is the pattern. See `character_log` opt-in for example.
- **`PARISH_USER_DATA_DIR` env var IS the full path.** No app-name suffix is appended. `/tmp/x` → all apps use `/tmp/x`, not `/tmp/x/Rundale`. Resolution is in `parish-persistence/src/paths.rs::resolve_user_data_dir`.
- **`parish-flags.json` is not loaded by `GameTestHarness`.** Runtime `/flag enable/disable` doesn't persist across script runs in the harness. For test-time flag behaviour, set `app.flags` directly.
- **`DayType` has three variants** (`Weekday`, `Sunday`, `MarketDay`). No `Holiday`. See `parish-types/src/time.rs`.
- **`parish --script` uses the active mod from `mods/mod-list.toml`.** `GameTestHarness::new()` loads Rundale, but live script mode currently follows `active_setting`; use a Rundale-only `PARISH_MODS_DIR` for Rundale-specific proof runs when the active setting is `testbed`.
- **`mods/mod-list.toml` selects the default setting mod when both Rundale and testbed exist.** Keep the checked-in value at `active_setting = "rundale"` unless a test explicitly switches it.
- **Demo profiling must isolate `PARISH_USER_CONFIG_DIR`.** Tauri reapplies saved wizard/category overrides from the user config dir after base env resolution, which can bypass a proxy unless the profiling run points config/data/saves at a temp directory.
- **Tauri demo reads per-category routing from user config, not category env vars.** `PARISH_INTENT_MODEL` works for the CLI config path, but Tauri startup hydrates category overrides from `PARISH_USER_CONFIG_DIR/parish.toml`.

## Character logs (`parish-core/src/character_log.rs`)

- **Profile section is rewritten every session**, journal is append-only. HTML comment markers `<!-- PROFILE_START -->` / `<!-- PROFILE_END -->` bound the rewritable region.
- **Dedup was removed in PR #1032 (89ab669d).** The bus now only publishes real physical movements (`schedule::tick_schedules`, `ticks::apply_tier3_updates`, `game_session::apply_movement`), so the writer is stateless beyond `log_dir`. Do not reintroduce `last_arrival` / `scan_existing_*` — they were obsoleted on purpose. (Issues #1013, #1014 closed because of this.)
- **Subscriber must rebind on branch switch.** Server (`parish-server/src/session.rs`) + Tauri (`parish-tauri/src/setup.rs`) + CLI (`App::rebind_log_managers_if_branch_changed`) each compare `current_branch_id` per event and rebuild the manager on mismatch. Otherwise post-`/load`/`/fork` events land under the old branch's `logs/branch-<old>/`. Same applies to `LocationLogManager` (#1011 #1034).

## rundale-bench local MLX sweep

- **mlx-lm 4-bit RAM footprint is roughly `params_b × 0.55 GB` peak under inference.** 70B+ 4-bit and 70B 8-bit OOM a 48 GB M5 Pro mid-generation (system reboot required). `magnum-v4-72b-4bit` and `Midnight-Miqu-70B-v1.5-MLX-8Bit` are marked `peak_ram_gb_est >= 52` in `rundale-bench/candidates_local_mlx.toml` so `local_runner.py`'s headroom check skips them. Don't lower without measuring on a bigger box.
- **`local_runner.py`'s "ready" signal is `/v1/models` returning 200, not actual model load.** Big-Tiger-Gemma-27B passed the readiness probe ~10 s before weights finished mmapping, so the first POSTs got HTTP 404 and the sweep recorded `overall=0.00` despite the model being viable later. On re-run it produced only `<pad>` tokens anyway — Gemma 4-bit quant is broken for in-character prose (same failure mode as `gemma-4-e4b-it-4bit`).
- **Qwen3 thinking-mode leaks unless `chat_template_kwargs={"enable_thinking": False}` is injected on mlx_lm.server requests.** `parish/scripts/local-eval/eval_lib.py::THINKING_MLX_PREFIXES` lists the affected repos. Without the flag, reasoning fills `max_tokens` and the assistant content is empty → near-zero rubric scores. Cloud reasoning models (kimi-k2.5/6, deepseek-r1, claude, openai-o\*, glm-4.6/7, gemini-2.5+) are already handled centrally by `_is_reasoning_model` → `_default_reasoning_for` in `eval_lib.py::call_chat`.
- **opencode.ai is fronted by Cloudflare which 403s the default Python-urllib UA** (firewall rule 1010). `call_chat` sets `User-Agent: rundale-bench/1.0 (+...)` so the request gets through.

## Agent + tooling gotchas

- **`gh pr view --json baseRepository` was removed** ("Unknown JSON field: baseRepository"). `parish/scripts/attach-proof.sh` no longer uses it — it derives `<owner>/<repo>` from `gh pr view --json url --jq .url` + `sed` (see the comment at attach-proof.sh:63-70). If you hit the error elsewhere, use the same parse. Fallback for posting the proof bundle by hand: `bash parish/scripts/render-proof-comment.sh <task-id> | gh pr comment <pr> --body-file -`.
- **`awk -v var=value` interprets backslash escapes in `value`.** `\n` becomes a real newline mid-string. To insert a multi-character literal containing `\n` (e.g. a `printf` format), write the trap to a temp file and use `getline < tf` inside `BEGIN`, not `-v`.
- **`gh pr edit` cannot change a PR's head branch.** If a sub-agent pushes a redo to `branch-v2` instead of the original branch, the PR keeps tracking the old SHA. Recovery: `git push origin +refs/remotes/origin/branch-v2:refs/heads/original-branch` to force-rewrite the PR's branch, then delete `branch-v2`.
- **Stop hooks under `set -euo pipefail` need `|| true` at the END of every command-substitution pipeline.** `grep` no-match exits 1 → pipefail propagates → silent exit. Visible only as "Stop hook error: Failed with non-blocking status code: No stderr output". All Stop hooks now have an ERR trap that surfaces future silent failures.
- **`PARISH_USER_DATA_DIR` only honors the FULL path** (no app_name appended). Tests setting `PARISH_USER_DATA_DIR=$tmp` should expect `$tmp/logs/branch-N/`, not `$tmp/<app>/logs/branch-N/`. See line 13 above; restated here because the rebind test (`headless.rs::rebind_log_managers_follows_branch_switch`) tripped on it.
- **CLI flag is `--game-mod <DIR>`, not `--mod`.** `parish --script ... --mod mods/rundale` errors with "unexpected argument". Use `--game-mod` (env: `PARISH_MOD`).
- **`build_site_data.py` reads committed proof-run mirrors by default.** Hermetic tests that pass temp artifact dirs must also point `PROOFS_RUNS_DIR` at an empty temp dir, or real `docs/proofs/rundale-bench/run_*.json` files leak into assertions.
- **Log subscribers must capture `location` at publish time, not re-resolve `npc.location` at consume time.** The `GameEvent` bus is async — a schedule tick can move the NPC between `publish` and the subscriber running — so resolving the destination from the NPC's _current_ location mis-files the entry (#1035). `DialogueOccurred`, `NpcInteraction`, and now `MoodChanged` + `LifeEvent` all carry an event-time `location`; the location-log subscriber routes by it. When adding a new event whose location matters, add the field and populate it at every publish site (the compiler enumerates them) — `MoodChanged`/`LifeEvent` had ~9 publish sites across `tier4.rs`, `banshee.rs`, `ticks.rs` (#1077/#1079).
- **Script mode (`parish-engine --script`) ignores `--game-mod`/`PARISH_MOD` entirely.** `main.rs` returns into `run_script_mode` _before_ `load_game_mod`, so the mod is chosen by `mods/mod-list.toml`'s `active_setting` (default `testbed`, not rundale). To run a Rundale proof transcript, temporarily set `active_setting = "rundale"` and restore it after — do not commit the flip.
- **`mods/rundale/npcs.json` field order must match `NpcFileEntry` struct declaration order.** The editor's `save_mod_byte_identical_to_source` test serialises via serde (struct order) and asserts byte-identity with the source file. When adding a field, place it in the JSON at the same position as in the struct (e.g. `pronouns` goes right after `personality`), or the round-trip test fails (#1026).
- **The per-turn dialogue chokepoint is now ONE function: `parish_core::game_session::apply_dialogue_turn`** (name detect, tier-1, conversation-exchange, witness memory, `DialogueOccurred` publish on `world.event_bus`, like `apply_movement`). All paths call it: live `run_npc_turn`, harness `consume_canned_npc_response` + `handle_npc_interaction_for`, headless `apply_npc_response`. Add new per-turn behaviour HERE only; guarded by `parish-engine/tests/mode_parity.rs` (#1172/#1173). These used to diverge silently (#1028 player-name, headless no-publish, addressed-path skips).
- **File tools (Read/Edit/Write) take absolute paths literally — in a worktree session they will open the MAIN checkout.** Editing `/…/Rundale/parish/…` hits the main tree while Bash (cwd = worktree) sees the worktree copy, so edits "succeed" but `cargo`/`git` never see them and worktree `git status` stays clean. Use the `.claude/worktrees/<name>/parish/…` path. Recover: `git -C <main> diff -- <f> >/tmp/p; git -C <wt> apply /tmp/p; git -C <main> checkout -- <f>`.
- **rundale-bench judge is Sonnet-subagent only — enforced at `load_judge`.** `local_runner.py --judge` historically defaulted to `judge_v1` = Qwen3-235B-via-OpenRouter, inflating round-4 dialogue scores by ~1.5 pts (OLMo-2-7B 4.78 under Qwen vs Sonnet's 3.28 on identical replies). Hard-locked 2026-05-28: `rundale_bench.load_judge` refuses any config whose `judge_via != "claude-code-subagent"` OR `model != "claude-sonnet-4-6"` OR `api_key_env != null`. HTTP-API judge files (`judge_v1.json`, `judge_pairwise_v1.json`) renamed `.disabled-2026-05-28-sonnet-only` so even the right id can't load them. If you add a new slice judge, ship those three invariants from day one.
- **The offline `simulator` inference backend does NOT write to the debug-snapshot `inference.call_log`** (only cloud/HTTP backends do). In a keyless sandbox (no `ANTHROPIC_API_KEY` etc.) dialogue falls back to the simulator, so you cannot capture a Tier-1 `prompt_text` via `GET /api/debug-snapshot` even though NPCs visibly reply. To prove dialogue-prompt _content_ (e.g. that location/context reaches the model) without a model, assert against the prompt-builder's output directly from the real world graph — e.g. `WorldState::from_parish_file("mods/rundale/world.json", id)` + `build_tier1_context` in an integration test (see `parish-npc/tests/tier1_context_real_world.rs`).
- **`just attach-proof` needs `gh`, which is absent in the web/MCP sandbox.** Replicate it by hand: `bash parish/scripts/agent-check.sh --source=local --bundle <id>` to validate, then post the body from `render-proof-comment.sh <id>` (or an equivalent fenced block) via the GitHub MCP `add_issue_comment` tool. CI's PR-mode gate extracts the `<!-- parish-proof-bundle:<id> v=1 -->` … `<!-- /… -->` fence and requires a clean `Evidence type: live gameplay transcript` line, a `### Acceptance criteria` heading, and `Verdict: sufficient` / `Technical debt: clear` / `Acceptance criteria: met` lines.
- **Opening a PR (even as draft) triggers the Agent proof gate immediately — it can run BEFORE your bundle comment lands**, so a create-then-comment sequence races and the first gate run fails spuriously. The gate reads PR comments at run time; just re-trigger with the next push (it re-runs on `synchronize` and finds the comment).
- **Playwright e2e (`apps/ui`) serves the app via `parish-server`, which reads `apps/ui/dist/` — a fresh checkout has no `dist/`, so EVERY e2e test fails with `getByText … resolved to 0 elements` (blank page), not an obvious build error.** Run `npx vite build` (or `pnpm build`) in `parish/apps/ui` first. Also: `pnpm install --frozen-lockfile` trips on the `"// overrides"` comment key in `package.json` (`ERR_PNPM_LOCKFILE_CONFIG_MISMATCH`); use `--no-frozen-lockfile` and don't commit the regenerated lockfile.
- **`mcp__parish__*` tools silently fail to register on a fresh worktree/clone if the `parish-mcp` binary isn't built at session init.** `.mcp.json` spawns the server at _session start_ to read its tool list; a missing binary means no tools register, with no in-session reload to recover — yet `claude mcp list` still shows the server `✓ Connected` (it reconnects lazily, after the roster is frozen), so the failure is invisible. The old `SessionStart--build-mcp.sh` async-built in the background and lost the race. Fixed (commit 3144b606): `.mcp.json` `command` is now `parish/scripts/parish-mcp-launch.sh`, which builds-if-missing then `exec`s, plus `MCP_TIMEOUT=900000` in `.claude/settings.json` so the one-time cold compile doesn't trip the startup timeout. If parish tools are ever absent mid-session, you can't reload them — restart Claude Code in the repo. To drive the game, prefer `mcp__parish__*` over raw curl / the `parish` HTTP client; the MCP `parish_file_bug` path is the only one that captures a screenshot to disk (needs a live frontend: `just run` / `just demo`, not the headless server).
- **Desktop screenshots capture native window pixels (xcap), NOT html-to-image, because the MapLibre minimap is a WebGL canvas that html-to-image cannot read.** The gameplay map draws cross-origin tiles, which taint the WebGL canvas so `canvas.toDataURL()` is blocked — the map serializes blank no matter what (`preserveDrawingBuffer` does NOT fix it). `do_take_screenshot` (parish-tauri) now captures the real window via `xcap` and only falls back to the frontend `html-to-image` round-trip when native capture is unavailable (no window / no macOS Screen-Recording permission / headless). Native capture needs the desktop window present + foreground; if a `parish_take_screenshot` comes back with a blank map, check the Tauri log for a `native screenshot failed` WARN (it fell back). Web mode (`parish-server`) has no window and still uses the browser-supplied html-to-image data URL. See #1160.
- **CI jobs default to `working-directory: parish` (`.github/workflows/ci.yml` `defaults.run`).** Any `run:` step that invokes a repo script must use a path relative to `parish/` (e.g. `bash scripts/foo.sh`), NOT `bash parish/scripts/foo.sh` — the latter resolves to `parish/parish/scripts/...` and dies with `No such file or directory` (exit 127). `actions/*` step inputs like `upload-artifact` `path:` are the exception: they're relative to the repo root (`GITHUB_WORKSPACE`), so `parish/target/...` is correct there. Mismatch between the two bit the `harness-shadow` job (#1159).
- **Non-Rust lint/format is now gated in CI + `just lint-all`** (alongside the Rust gates). Per language: TS/Svelte = ESLint flat config (`parish/apps/ui/eslint.config.js`) + Prettier (`.prettierrc`); docs/data = root Prettier (`prettier.config.js`, scoped to `**/*.{md,json,jsonc,yml,yaml}`) + markdownlint (`.markdownlint-cli2.jsonc`); Python = ruff + mypy + pytest + yamllint (`pyproject.toml`, `requirements-dev.txt`, local venv `.venv-dev`); shell = shellcheck + shfmt (`.shellcheckrc`, flags `-i 4 -ci -bn`); TOML = taplo (`taplo.toml`). Gotchas: (1) the UI uses **npm + node 22 via fnm** — node 26 + `engine-strict=true` makes `npm install` abort, so `fnm use 22` before any `npm`/`npx`. (2) `.prettierignore` is **gitignore syntax — no inline comments** (a `path  # note` line is treated as a literal pattern and silently fails to ignore). (3) taplo must run with `array_auto_collapse=false`, `array_auto_expand=false`, `align_comments=false`, `indent_string="    "`, and exclude globs need `**/target/**` (not `target/**`) or it mangles the hand-curated mod arrays and scans build artifacts. (4) yamllint must `disable` the `braces` rule — GitHub Actions `${{ }}` reads as flow-mapping braces. (5) the auto-fmt Claude hook (`.claude/hooks/PostToolUse--auto-fmt.sh`) now formats by extension (prettier/ruff/shfmt/taplo). (6) running pytest/mypy/ruff creates `.pytest_cache`/`.mypy_cache`/`.ruff_cache` — all gitignored AND in the prettier/markdownlint ignores.
