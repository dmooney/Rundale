# Road Topology Cue Cycle AS

## Purpose

Cycle AS tries to create a deterministic road/topology cue after Cycle AR showed
that prompt text and tighter crops still let the model regularize roads into a
centered scenic Y/crossroads.

The cue is generated by extending `scripts/prototype_map_controls.py`; it uses
only pixel data from the cleaned map crop, with no hand-authored location notes.

## Inputs

- `pipeline-experiments/idea-ar-kilteevan-playable-no-admin-map-crop.png`

## Outputs

First heuristic:

- `pipeline-experiments/idea-as-kilteevan-playable-roadcue-road-topology-control.png`
- `pipeline-experiments/idea-as-kilteevan-playable-roadcue-road-topology-oblique.png`

Tightened heuristic:

- `pipeline-experiments/idea-as2-kilteevan-playable-roadcue-road-topology-control.png`
- `pipeline-experiments/idea-as2-kilteevan-playable-roadcue-road-topology-oblique.png`

Both runs also produced the usual ink, semantic, linework, oblique, and
blockout artifacts from `prototype_map_controls.py`.

## Result

Do not use these road-cue artifacts as image-generation authorities.

The first heuristic highlighted broad tan blobs around most dark ink and tree
symbols, not just road corridors. The second heuristic reduced some immediate
ink-adjacent noise but still over-selected tree/symbol clusters and pale spaces
around mapped marks. Neither output is legible enough as a road geometry cue.

This is a useful negative result: the road-control problem probably needs a
more deliberate topology extraction step than pale-corridor thresholding. Until
that exists, prefer the raw map/control crop and oblique raw warp over these
road-cue masks.

## Next Direction

Return to the earlier successful topology idea: use a two-step
top-down-cleaned-to-isomorphic path on the tighter playable crop, while keeping
AQ/AR's no-chimney roof language and single-building style-reference hygiene.
