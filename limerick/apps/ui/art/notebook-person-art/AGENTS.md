## Local gotchas

- **Production art pipeline means metadata-to-art end-to-end unless explicitly narrowed.** For notebook/person-art issues, source-of-truth NPC/world metadata must drive prompt/job generation, provider/model calls, receipts, candidate artifacts, approval/promotion, runtime assets, provenance, screenshots, and proof; reviewed source-sheet assembly alone is only a downstream stage.
- **`gpt-image-2` cannot currently emit transparent backgrounds.** Notebook person generation uses the pinned model with the concept image through `/v1/images/edits`, requests a flat `#ff00ff` raw background, then validates and removes the key locally; never bake parchment into portrait output or pin production to a deprecated model solely for alpha.
- **Persist image-provider raw bytes before content validation.** A real #1628 smoke image failed the four-corner chroma check, and the first runner version discarded the paid response before it could be inspected; rejected outputs now keep raw bytes, hashes, request metadata, and failure receipts.
- **Portrait and marker art directions cannot share one flattened provider prompt.** The first #1628 API portrait inherited painted-world watercolor/color language and a full-scene reference, then passed a format-only validator as a polished illustration. Route references by asset kind, lead portrait prompts with the diegetic player-sketch fiction, and gate sparse ink bounds/fill/density before human review.
- **Do not run Prettier over generated art-input JSON after recording provenance.** `npc-art-inputs-v1.json` is owned by `limerick-npc-tool`; whitespace-only reformatting changes its byte hash even though canonical job IDs stay stable. Keep it in `.prettierignore` and regenerate it with the owning tool.
- **Paired image requests must compose both complete child contracts.** A generic two-cell layout prompt dropped the proven portrait no-underpainting rule and produced cream-filled art; build pair prompts mechanically from the pair layout plus full portrait and marker contracts, and test all three reach the provider request.
- **Portrait color validation must distinguish fill from keyed ink edges.** Sparse sepia strokes blended against opaque magenta can look highly chromatic numerically; retain a total chroma ceiling, but use an eroded interior mask to reject solid color fill without rejecting one-pixel antialias fringes.
- **Chroma-key despill must inspect opaque retained pixels too.** GPT image output can bake dark-magenta blends outside the alpha-feather radius; partial-alpha-only cleanup leaves a purple runtime halo. Neutralize palette-forbidden magenta-balanced pixels at any alpha and gate residual spill among visible pixels.
- **Provider framing variance is mechanically normalizable when the figure is complete.** The first 22-NPC #1628 batch produced eight otherwise-valid pairs outside fixed height ceilings; reject edge-touching/cropped art, but downscale and recenter complete keyed subjects deterministically, recording before/after bounds and migrating old raws without another provider call.
- **Anonymous art fallbacks need identity contrast from named style references.** Two #1628 fallback calls copied the female Roisin reference's kerchief, shawl, apron, and face despite a generic brief; explicitly choose a non-conflicting anonymous identity and ban the reference subject's identity cues while preserving only its line/wash style.
- **Art-direction coverage is not identity completeness.** One free-text appearance sentence per NPC can satisfy a coverage check while supplying only age and mood; a shared full-face image-edit reference then becomes the strongest identity signal and collapses under-specified cohorts onto one face. Require structured geometry plus cast-level collision and visual-distinctiveness gates before generation is called review-ready.
- **Key-background drift must not define subject bounds.** An opaque image response can shift an otherwise flat `#ff00ff` border just beyond the strict removal threshold; compute crop/framing bounds outside the wider configured key-feather radius, while keeping true high-distance subject pixels at the edge as hard crop failures.
- **Period-plausible hair prose can still collapse a generated cast.** Keep face geometry independent from machine-comparable hair front/rear/covering/silhouette families, reject repeated topologies within cohorts, and require a separate whole-cast hairstyle approval.
- **Global image-provider failures need a queue circuit breaker.** Billing/auth/model errors are batch-wide, so stop after the bounded in-flight requests and leave untouched content-addressed jobs pending for exact retry; never emit millions of duplicate failure attempts.
- **Review-only art metadata still needs per-subject provenance.** Keep structured topology out of provider job identity when the prompt already compiles it, but bind its exact vector/digest into pair and whole-cast decisions and replay that one record at promotion.
- **Marker readability must come from the character, not occupational props.** A required `readable_props` field turned tiny NPC markers into narrative vignettes; use a character-only schema with explicit empty-hand poses, intrinsic cues, and review gates against objects, scenery, ground planes, shadows, and extra people.
- **Billable request ceilings must count HTTP attempts, not planned jobs.** Provider retries can otherwise exceed an operator's spend cap; journal each attempt before validation and stop dispatch when the actual-call budget is exhausted.
- **Metadata and documentation path checks must inspect new git-index paths after a rename.** Frozen art relative paths can survive a directory rename without rehashing; validate the indexed path mapping before changing any recorded bytes.
