# limerick-core — agent scope

Backend-agnostic composition + orchestration crate. Owns game session orchestration (`game_session`, `game_loop/`), the IPC layer (`ipc/`), and prompt templates. Re-exports all leaf crates (`chronicle`, `config`, `diagnostics`, `editor`, `inference`, `input`, `mod`, `npc`, `palette`, `persistence`, `providers`, `setup`, `types`, `world`) under stable paths. See root [`AGENTS.md`](../../../AGENTS.md).

## Scoped commands

```sh
cargo test -p limerick-core                                # unit + arch fitness
cargo test -p limerick-core --test architecture_fitness    # module-ownership + mode-parity enforcement
cargo doc  -p limerick-core --no-deps --open               # composed surface
```

## Local gotchas

- **Architecture-fitness test ([module ownership](../../../docs/agent/engineering-rules.md#module-ownership), [mode parity](../../../docs/agent/engineering-rules.md#mode-parity) and [cross-runtime orchestration](../../../docs/agent/engineering-rules.md#cross-runtime-orchestration)).** Rejects backend-agnostic crates depending on `tauri`, `axum`, `tower*`, `wry`, `tao`, and orphan source files (on disk, no `mod` decl). Run before any commit adding `mod` declarations or crate deps.
- **`EventEmitter` is the seam ([cross-runtime orchestration](../../../docs/agent/engineering-rules.md#cross-runtime-orchestration)).** All new orchestration in `game_loop/`, IPC handlers, and payload structs must be defined here parameterized over `EventEmitter`; entry-point crates supply their own emitter (#687, #696). No copy-paste into `limerick-server` / `limerick-tauri` / `limerick-engine`.
- **Re-exports are load-bearing.** Preserve `limerick_core::*` names when refactoring — every entry point depends on them. Extraction shims (`crate::game_mod`, `crate::editor`, `crate::{character_log, location_log, chat_transcript}`, `crate::debug_snapshot`, `crate::ipc::bug_report`) are part of this contract.
- **`desktop` (default) / `mobile` Cargo features.** `mobile` (`--no-default-features --features mobile`) excludes `limerick-setup`, `hf-hub`, the Ollama/vllm `inference::client`, `limerick-editor`, `limerick-chronicle`, and `limerick-diagnostics`, and so compiles out `ipc`, `game_loop`, and `game_session`, which depend on them. Keep new portable code out of those modules, and never gate `limerick-mod` or `limerick-palette` (no desktop dependencies). CI's `rust-mobile-build` job runs `cargo check -p limerick-core --no-default-features --features mobile`.
- **[Scaling guardrails](../../../docs/agent/engineering-rules.md#scaling-guardrails).** Edits to `AppState`, session persistence, real-time push, inference calls, identity lookups, or mod loading require review against [`docs/agent/scaling-rules.md`](../../../docs/agent/scaling-rules.md).

- **Clock-boundary tests must normalize their anchor.** Pausing a fixture clock preserves elapsed seconds from fixture loading; normalize to the start of the minute before sampling 0/1/59/60 seconds, or coverage overhead can make a within-minute sample cross the boundary.
- **`apply_movement` (in `limerick-core/src/game_session.rs`) is the lowest-shared movement seam.** Tauri/server reach it via `game_loop::movement::handle_movement`; the script harness calls `apply_movement` directly. Publish movement-related events there for parity.
- **The world-advance pump is `limerick_core::game_loop::advance_world` (#1159) — the ONE place weather/schedules/tiers/banshee/gossip/tier-4 are ticked.** Each runtime selects atoms via `AdvanceOptions` (server: budgeted gossip; Tauri: all gossip; headless: no gossip; harness per-turn: partial, `advance_time`: full); every real Tier 4 pump derives its default-on kill switch through `tier4_simulation_enabled`. RNG order is weather→gossip→tier-4. Don't re-inline these atoms into an entry-point loop.
- **The per-turn dialogue "apply" step is one shared seam now: `limerick_core::game_session::apply_npc_dialogue_turn`** (#1172 / #1173). It does the five cross-cutting steps — name detection, `apply_tier1_response_with_config`, `conversation_log.add`, `record_witness_memories`, and the `DialogueOccurred` publish — and is called by all four turn paths (`game_loop/npc_turn.rs`, headless `apply_npc_response`, and the harness `consume_canned_npc_response` + `handle_npc_interaction_for`). Before this, those paths each did a _different subset_ and drifted: the harness silently skipped `detect_and_record_player_name` (player stuck as "A stranger", #1028), headless never published `DialogueOccurred`, the addressed harness path (`talk to X`) dropped witness memories + conversation log. **Add any new per-turn behaviour to the seam, not to a call site** — `limerick-engine/tests/mode_parity.rs` (the parity golden) asserts the legacy harness and the real `game_loop` emit an identical `GameEvent` stream and will fail if a path diverges. Note: each entry point still keeps a _pre-inference_ `detect_and_record_player_name` so this turn's prompt sees a just-introduced name; the seam's repeat call is idempotent.
- **NPC dialogue has a deterministic anti-repetition backstop now: `limerick_npc::guard_against_repetition`** (#1228). Small/quantized models (the local MLX Qwen2.5-14B-4bit) loop a single clause dozens of times in one reply or echo their own previous line near-verbatim; the #1224 length cap only clips the tail and does nothing across turns. The guard runs inside the shared seam `apply_npc_dialogue_turn` (limerick-core/game*session.rs) \_before* the length cap: it collapses consecutive normalized-equal clauses (`collapse_repeated_sentences`) and, when the result is near-identical (word-level Jaccard ≥ `NpcConfig::dialogue_repetition_threshold`, default 0.92) to the NPC's own previous line at this location (read from `world.conversation_log`), substitutes `varied_repetition_fallback`. **`apply_npc_dialogue_turn` now returns `DialogueTurnOutcome { debug_events, display_text }`, not `Vec<String>`** — every entry point must render `display_text` (the one guarded+capped line), never re-derive a player line from `parsed.dialogue`, or it bypasses both guards. The live headless _streaming_ print still shows raw tokens (can't guard mid-stream; relies on `frequency_penalty` at the inference layer) but the stored/recorded copy is guarded. It's fully deterministic — no live LLM needed for the unit/integration tests.
- **Inference reloads must publish routes and their already-built clients as one epoch.** Keeping a resolved config lock beside independently rebuilt `client`/`cloud_client` locks lets admitted requests observe mixed generations; use `InferenceRuntimeManagerV2` and capture one snapshot at request/session admission.
- **Atomic journal inserts do not order state capture against autosave.** Hold one lifecycle barrier from pre-mutation capture through journal commit, and from autosave capture through snapshot commit; rejected staged turns must leave NPC, conversation, logs, events, and tasks unchanged.
- **`introduced_npcs` is durable player-earned knowledge, not session grounding state.** A snapshot already persists it; do not clear it after server/Tauri/headless restore. Legacy saves whose set was emptied by the old restore path may be healed only from retained final NPC dialogue that passes the same strict roster-aware identity detector used at the canonical apply seam.
- **Background-simulation claims must follow `advance_world` in the same critical section.** `apply_movement` reassigns tiers before ticking schedules, so an NPC who arrives during the player's travel keeps a stale tier until the next pump; a Tier-2/Tier-3 due check on its own timer sees stale or refreshed tiers depending on which timer fires first, so the set of simulated groups varies between identical runs (#2078).
- **A parked turn must keep counting call ids and event ordinals.** An attempt that resumes after a clarification reuses its attempt id, so resetting `calls_issued` would let a late reply to a pre-question call answer a re-run call, and restarting event ordinals would collide with journaled event ids. `RequestAttempt::next_event_ordinal` records where the attempt's journaled events end; restart recovery numbers from it.
- **A failed turn records none of the player's words.** Since #2035 every turn runs on a candidate, so pronoun antecedents, referents, and recorded input from a failed dialogue turn are discarded with it; a follow-up test needs its antecedent from a committed exchange.
- **A turn's durable state is the save, not the engine.** Since #2037 every committed turn writes its request, transcript events, task batch, and a snapshot of the installed state in one SQLite transaction, and `InProcessTurns::open` must run _after_ the runtime replaces its save identity (launch, new game, load, fork); opening against the old target restores the wrong branch's journal. Forks start an empty turn history at revision 0.

## Module map

`game_session.rs` runtime session, `game_loop/` tick + movement, `ipc/` shared types + handlers (incl. `bug_report` shim), `endpoint_input.rs` Endpoint reference + structured input attached to intent/dialogue `InferenceCall`s, `loading.rs`+`mod_source.rs` mod-load wiring (loader in `limerick-mod`), `prompts/` templates, `event_bus.rs`, `identity.rs`, `secret_store.rs`, `session_store.rs`, `tile_cache.rs`. Extracted + re-exported: `limerick-mod` (content-mod loader), `limerick-editor` (Designer backend), `limerick-chronicle` (character/location/chat logs), `limerick-diagnostics` (debug snapshot + bug report).
